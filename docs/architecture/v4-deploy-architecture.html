สถาปัตยกรรมการ deploy ระบบ V4

CS361 G650-15 · วงจรความร่วมมือและการปรับปรุง · AWS ap-southeast-2 (Sydney) · บัญชีใหม่แบบประหยัด

#ขั้นตอนรายละเอียด
1เปิดเว็บHTTPS ไปยัง Amplify ซึ่งรัน Next.js ทั้งหน้าสาธารณะ แดชบอร์ดตามบทบาท และฟอร์มเพิ่มหรือแก้ไขข้อมูล
2Proxy APINext.js rewrite /api/v1/* ไปที่ API_PROXY_TARGET = http://<Elastic IP>:8000 เบราว์เซอร์จึงเรียก API จาก origin เดียวกับหน้าเว็บ หลังเข้าสู่ระบบ ทุกคำขอแนบ Authorization: Bearer <token> Elastic IP ทำให้ค่านี้ยังใช้ได้หลัง stop/start เครื่อง
3เข้าสู่ระบบและตรวจสิทธิ์POST /auth/login ให้ backend ส่งอีเมลและรหัสผ่านไปตรวจที่ Cognito pool cstu-v3-auth คำขอถัดไป auth.py ตรวจลายเซ็น token กับ JWKS แล้วตรวจสิทธิ์ด้วย require_role(...) เหมือน V3
4อ่านและเขียนข้อมูลFastAPI ต่อ PostgreSQL ที่ cs361-db:5432 ผ่าน Docker network พอร์ตฐานข้อมูลไม่เปิดออกนอกเครื่อง ข้อมูลอยู่ใน /opt/cs361/pgdata บน EBS gp3 ที่เข้ารหัส ทุกการแก้ไขยังบันทึก audit_logs ใน transaction เดียวกัน
5ไฟล์backend อ่าน เขียน และลบไฟล์บน S3 ด้วย IAM role ของเครื่อง ได้แก่ PDF ข้อตกลง และไฟล์ CSV/XLSX ที่นำเข้า (เก็บชั่วคราวระหว่างตรวจ แล้วลบเมื่อตรวจเสร็จ) bucket ปิดการเข้าถึงสาธารณะ เปิด versioning และเข้ารหัส
6Deploy หน้าเว็บpush เข้า main บน GitHub แล้ว Amplify build (app root frontend) และ deploy ให้เอง
7Deploy backend และสำรองข้อมูลรัน deploy.sh จาก CloudShell โดยอัปโหลด backend/ ขึ้น S3 แล้วสั่งเครื่องผ่าน SSM Run Command ให้ build และเปิด container ใหม่ (API หยุดไม่กี่วินาที) คำสั่ง backup รัน pg_dump แล้วเก็บที่ s3://…/backups/

เพิ่มใน V4

  • ความคิดเห็นจาก 4 บริบท พร้อมตอบกลับ ตรวจสอบ และเผยแพร่
  • ผลลัพธ์พร้อมหน่วยนับ และการปรับปรุงที่ผูกกับความคิดเห็น (PDCA)
  • การตัดสินใจต่ออายุ และสายข้อตกลงฉบับเดิมไปฉบับใหม่
  • นำเข้า CSV/XLSX แบบตรวจก่อนยืนยัน ส่งออก CSV และรายงานรายปี

เปลี่ยนจาก V3

  • ย้ายไปบัญชีใหม่ที่ Sydney
  • RDS → PostgreSQL container บน EC2 (ประมาณ $15 ต่อเดือน)
  • Elastic IP · SSM แทน SSH · สร้างด้วย CloudFormation

ยังไม่ได้ใช้

  • Multi-AZ หรือฐานข้อมูลแยกเครื่อง
  • HTTPS ระหว่าง Amplify กับ EC2
  • Load balancer, Auto Scaling
  • สำรองข้อมูลอัตโนมัติ
