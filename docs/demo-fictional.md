# ชุดข้อมูลสมมติสำหรับสาธิต CSTU

วันที่ 2 ตุลาคม 2026 เปลี่ยนแนวทางการนำเสนอเป็นข้อมูลสมมติที่ครอบคลุม
สถานการณ์ของโจทย์ ข้อมูลจริงที่รวบรวมไว้ยังคงอยู่ในฐานข้อมูลเดิม
ไม่ผสมและไม่แทนที่ข้อมูลจริงด้วยชื่อหรือข้อตกลงสมมติ

## เริ่มเดโม

```powershell
docker compose -f docker-compose.demo.yml up --build -d --wait
```

เปิด http://localhost:3100/dashboard/public และดูป้าย “ข้อมูลสมมติสำหรับสาธิต”
เว็บข้อมูลจริงเดิมอยู่ที่ http://localhost:3000/dashboard/public

เดโมใช้ PostgreSQL `cstu_demo` ใน Compose project `cs361-demo`
กับ volumes `cs361-demo_demo_postgres_data` และ `cs361-demo_demo_backend_storage`
ไม่มีการเชื่อมต่อ RDS หรือฐานข้อมูล `cstu_collaboration`
รหัสผ่านใน Compose เป็นค่าท้องถิ่นสำหรับเดโม; DB/API ไม่มี host port ที่เปิดให้ภายนอก

## ข้อมูลและสถานการณ์

| ข้อมูล | ทั้งหมด | เผยแพร่ | ตัวอย่าง |
| --- | ---: | ---: | --- |
| Stakeholder | 12 | 11 | มหาวิทยาลัย บริษัท หน่วยงานรัฐ เครือข่าย ศิษย์เก่า ผู้เชี่ยวชาญ องค์การนานาชาติ |
| เอกสาร | 8 | 7 | ข้อตกลงใช้งาน ใกล้หมดอายุ หมดอายุ ฉบับร่าง และแบบฟอร์ม |
| กิจกรรม | 15 | 14 | สัมมนา ฝึกงาน แลกเปลี่ยน เยี่ยมชม ประชุม กิจกรรมที่ไม่มี MoU และวันที่ไม่ทราบ |

เอกสารสาธารณะมี 6 ข้อตกลงและ 1 แบบฟอร์ม เพื่อทดสอบว่า KPI ข้อตกลง
ไม่นับแบบฟอร์ม PDF ที่ดาวน์โหลดเป็นเอกสารสมมติเฉพาะแต่ละรายการ
ไม่ใช่สัญญาและไม่ใช่หลักฐานทางการของหน่วยงานใด
มีเอกสาร metadata-only และเอกสารที่ระบุว่าไฟล์ไม่พร้อมใช้งาน
ข้อมูลติดต่อทั้งหมดใช้ชื่อสมมติและโดเมน `example.test`
บางรายการไม่อนุญาตเผยแพร่ข้อมูลติดต่อ เพื่อทดสอบการจำกัดการเปิดเผย

แหล่งที่มาระบุ `demo_fixture`; สถานะ `verified` ในชุดนี้หมายถึงความสอดคล้อง
ของ fixture เท่านั้น ไม่รับรองความร่วมมือจริง หน้า detail ไม่เปิดลิงก์แหล่งที่มาสมมติ
บุคคลใช้ `partners.type=alumni/expert` ผ่านสัญญา API เดิม
ยังไม่ถือว่าได้ทำระบบจัดการบุคคล สิทธิ์ หรืองานภายในของ V3 ครบ

สถานะข้อตกลงเป็น snapshot ณ วันที่สร้างชุดข้อมูล 2 ตุลาคม 2026
ข้อมูลชุดนี้เหมาะสำหรับตรวจฟังก์ชันและเดโม V2; V6 ต้องเพิ่มชุดข้อมูลขนาดใหญ่
ตามแผนทดลองและวัดผลแยกต่างหาก

## เส้นทางเดโม

1. Stakeholder: กรองศิษย์เก่า/ผู้เชี่ยวชาญ แล้วเปิดรายละเอียดบุคคลและกิจกรรม
2. เปิดมหาวิทยาลัยรุ่งอรุณวิทยา → MoU แลกเปลี่ยน → กิจกรรม → กลับ Stakeholder
3. ค้นหา/กรองประเภท สถานะ และช่วงเวลาในหน้าเอกสาร แล้วดาวน์โหลด PDF
4. เปิดรายการ metadata-only/ไฟล์ไม่พร้อมใช้งาน และตรวจว่าปุ่มดาวน์โหลดไม่แสดง
5. กรองกิจกรรมและเปิดกิจกรรมของศิษย์เก่าที่ไม่มี MoU; refresh รายละเอียดยังคงอยู่
6. ค้นหาคำที่ไม่มีผลลัพธ์ ตรวจ Empty state; ทดสอบ API 404 ของข้อมูลภายใน

## รันเตรียมข้อมูลซ้ำ

```powershell
docker compose -f docker-compose.demo.yml run --rm seed
docker compose -f docker-compose.demo.yml stop
docker compose -f docker-compose.demo.yml up -d --wait
```

Seed ทำงานเฉพาะ PostgreSQL ชื่อ `cstu_demo` และ local storage
เตรียมครั้งแรกต้องเป็น DB ว่าง รันซ้ำของ version เดิมไม่เพิ่ม/ลบ/เขียนทับข้อมูล
รองรับการยกระดับ `cstu-fictional-v1` เป็น `cstu-fictional-v2` ที่ผู้ใช้อนุมัติ:
เพิ่มรายละเอียดบุคคล/หน่วยงาน กิจกรรม ขอบเขตข้อตกลง และ PDF เฉพาะรายการ
รักษา ID และจำนวนข้อมูลเดิม ตรวจว่าทุกรายการมาจาก `demo_fixture` ก่อนแก้ไข
หาก version หรือจำนวนข้อมูลต่างจากชุดเดิมจะหยุดให้ตรวจ ไม่ reset อัตโนมัติ
`stop` เก็บข้อมูลและไฟล์ไว้ใน volumes

หลักฐานข้อมูลสมมติไม่ใช่หลักฐานว่ามีผู้ใช้จริงหรือมีความร่วมมือจริง
การรับ Feedback จากผู้ใช้จริงและการส่งงานตามเวอร์ชันยังต้องมีหลักฐานของตนเอง

## รายละเอียดและ S3 ที่เพิ่มภายหลัง

ทุก Stakeholder มีบทบาท เป้าหมาย ประวัติ และผู้ประสานงานเฉพาะบริบท
ทุกกิจกรรมมีวัตถุประสงค์ กลุ่มเป้าหมาย กำหนดการ และผลลัพธ์/งานถัดไป
เน้นเรื่องแลกเปลี่ยนนักศึกษา ฝึกงาน และศิษย์เก่าร่วมพัฒนาหลักสูตร
กิจกรรมอนาคตไม่อ้างว่ามีผลลัพธ์แล้ว และวันที่เปิดรับสมัครไม่ใช้แทนวันจัดกิจกรรม
เอกสารที่มีไฟล์ 6 รายการมี PDF ต่างกัน (4 ข้อตกลงสาธารณะ, 1 ฉบับร่างภายใน,
1 แบบฟอร์มสาธารณะ) อีก 2 รายการคงเป็น metadata-only/ไฟล์ไม่พร้อมใช้งาน

เครื่องนี้เปิด S3 แล้ว ให้ restart ด้วย Compose ทั้งสองไฟล์ตาม
[คู่มือ S3](demo-s3.md) การใช้ Compose หลักไฟล์เดียวจะกลับไปใช้ local storage
ซึ่งยังเก็บสำเนาเดโมไว้สำหรับพัฒนาในเครื่อง
