# คู่มือคำศัพท์และน้ำเสียงหน้าเว็บ (PCSMS)

คู่มือนี้ใช้กับข้อความทุกข้อความที่ผู้ใช้เห็นใน `frontend/src` ได้แก่ หัวข้อ ปุ่ม ป้ายช่องกรอก ข้อความแจ้งผล ข้อความผิดพลาด และหน้าว่าง
เขียนขึ้นจากการอ่านข้อความภาษาไทยทั้งหมดในหน้าเว็บ (ประมาณ 700 ข้อความ) เมื่อ ต.ค. 2569

## 1. น้ำเสียง

ผู้ใช้หลักคืออาจารย์และเจ้าหน้าที่หลักสูตร ข้อความควรสุภาพ ตรงไปตรงมา และอ่านแล้วรู้ทันทีว่าต้องทำอะไร เหมือนเจ้าหน้าที่ที่คุ้นงานอธิบายให้เพื่อนร่วมงานฟัง ไม่ใช่เอกสารราชการและไม่ใช่คู่มือโปรแกรม

1. **ไม่ลงท้ายด้วยครับ/ค่ะ** และไม่ใช้คำเล่น
2. **ละ "คุณ" เมื่อบริบทชัดอยู่แล้ว** ภาษาไทยไม่ต้องมีประธานทุกประโยค
   - ✗ กิจกรรมที่คุณบันทึกจะยังไม่เผยแพร่ จนกว่าเจ้าหน้าที่จะอนุญาต
   - ✓ กิจกรรมใหม่จะแสดงในหน้าสาธารณะเมื่อเจ้าหน้าที่เผยแพร่
3. **ใช้ประโยคที่บอกว่าใครทำ แทนประโยค "ถูก..."** ซึ่งเป็นสำนวนแปลจากภาษาอังกฤษ
   - ✗ ข้อมูลส่วนตัวนักศึกษาถูกปกป้องตาม PDPA การแสดงผลถูกควบคุมตามสิทธิ์ผู้ใช้
   - ✓ ระบบแสดงข้อมูลนักศึกษาตามสิทธิ์ของแต่ละบทบาท ตาม PDPA
4. **ไม่ต่อ "ที่...ที่..." ซ้อนกัน** ถ้าวลียาวเกินไปให้แยกเป็นสองประโยค
   - ✗ ยังไม่มีข้อตกลงที่เกี่ยวข้องที่เผยแพร่
   - ✓ ยังไม่มีข้อตกลงที่เกี่ยวข้อง
5. **ขอร้องด้วย "กรุณา" คำเดียวทั้งระบบ** (ตอนนี้ปน "โปรด" อยู่) และใช้เฉพาะคำแนะนำหรือข้อความผิดพลาด ปุ่มไม่ต้องมีคำสุภาพ
6. **ไม่อธิบายกลไกภายในของระบบให้ผู้ใช้อ่าน** เช่น เงื่อนไขการกรองแบบสเปก รหัส HTTP หรือหมายเหตุของนักพัฒนา ("ยังไม่แยกตามผู้รับผิดชอบ", "จะแสดงเมื่อระบบรองรับบัญชีนักศึกษา")
7. **ใช้ภาษาอังกฤษเฉพาะชื่อเฉพาะและคำย่อที่คนไทยใช้กันจริง** ได้แก่ MoU, MoA, PDF, CSV, PDPA, CSTU ส่วนคำอย่าง Feedback, Export, System, Access Log, audit log, ISO ให้ใช้คำไทย
8. **ป้ายหนึ่งป้ายใช้ชื่อเดียว** ไม่ใช้เครื่องหมาย / รวมสองชื่อ เช่น "อาจารย์ / ผู้ประสานงาน" ให้เลือกชื่อเดียว

## 3. รูปแบบข้อความแต่ละชนิด

**ปุ่ม**: กริยา + สิ่งที่ทำ สั้นที่สุดที่ยังชัด ไม่มีคำสุภาพ
- กล่องเพิ่มข้อมูลใช้ปุ่ม "เพิ่ม" ส่วนกล่องแก้ไขใช้ "บันทึก"
- ปุ่มปิดกล่องใช้ "ยกเลิก"

**ป้ายช่องกรอก**: คำนามสั้น ๆ ไม่ใส่คำอธิบายหรือรูปแบบข้อมูลในวงเล็บ ให้ย้ายไปไว้ในข้อความช่วยเหลือใต้ช่อง
- ✗ ลิงก์แหล่งที่มาที่ตรวจแล้ว (https://)
- ✓ ลิงก์แหล่งที่มา · ข้อความช่วยเหลือ: "ลิงก์ที่ตรวจแล้วว่ายืนยันข้อมูลนี้ได้ ขึ้นต้นด้วย https://"

**ข้อความแจ้งผลสำเร็จ**: "<การกระทำ><สิ่งที่ทำ>แล้ว" ระบุชื่อในเครื่องหมายคำพูดได้เมื่อมีหลายรายการ
- ✓ เพิ่ม “สัมมนา AI” แล้ว
- ✗ เปลี่ยนสถานะเป็น “อนุมัติแล้ว” แล้ว (มี "แล้ว" ซ้ำสองครั้ง) → ✓ อนุมัติข้อตกลงแล้ว

**ข้อความผิดพลาด**: บอกว่าเกิดอะไรขึ้น ตามด้วยสิ่งที่ผู้ใช้ทำได้ ไม่แสดงรหัสภายใน
- ✗ เกิดข้อผิดพลาด (HTTP 500)
- ✓ บันทึกไม่สำเร็จ กรุณาลองอีกครั้ง
- ✗ ทำรายการนี้ไม่ได้ในสถานะปัจจุบัน (approved)
- ✓ ข้อตกลงนี้อนุมัติแล้ว จึงเปลี่ยนกลับเป็นฉบับร่างไม่ได้

**กล่องยืนยัน**: ถามเป็นคำถาม แล้วบอกผลที่จะเกิดขึ้นในประโยคถัดไป
- ✗ ยืนยันยกเลิกข้อตกลงนี้? ย้อนกลับไม่ได้
- ✓ ยกเลิกข้อตกลง “…” ใช่ไหม · การยกเลิกย้อนกลับไม่ได้

**หน้าว่าง**: บอกว่ายังไม่มีอะไร และถ้าผู้ใช้เพิ่มได้ ให้บอกว่าต้องกดปุ่มไหน
- ✓ ยังไม่มีกิจกรรม · กด “เพิ่มกิจกรรม” เพื่อเริ่ม

**ช่องค้นหา**: บอกว่าค้นจากอะไรได้บ้าง ไม่ต้องลงท้ายด้วย "..."
- ✓ ค้นหาชื่อกิจกรรมหรือหน่วยงาน

**วันที่**: วัน เดือนย่อ ปี พ.ศ. เช่น 5 ธ.ค. 2569 ใช้รูปแบบเดียวกันทุกหน้า

## 4. ตัวอย่างจากหน้าเว็บจริง

|---|---|---|

## 5. วิธีแก้

- แก้ทีละหน้า และแก้คำใน `lib/labels.ts` กับ `lib/role-context.tsx` ก่อน เพราะทุกหน้าใช้ร่วมกัน
- ชุดทดสอบใน `frontend/tests/` (เช่น `v3-functional.cjs`, `v3-agreements.cjs`) หาปุ่มและช่องกรอกจากข้อความภาษาไทย ต้องแก้ข้อความในชุดทดสอบไปพร้อมกับหน้าใน commit เดียวกัน
- ข้อมูลตัวอย่างที่ฝังไว้ในหน้า reports, users และ settings ไม่อยู่ในขอบเขตคู่มือนี้ เพราะจะถูกแทนด้วยข้อมูลจริงตามงานใน #79

## 6. ข้อตัดสินใจ (ต.ค. 2569)

1. **ชื่อบทบาท admin** ใช้ "ผู้ดูแลระบบ" ทั้งชื่อเต็มและชื่อย่อ
2. **ป้าย "ของคุณ"** ในตารางรายการยังใช้คำเดิม เป็นข้อยกเว้นเดียวของข้อ 2 ในหัวข้อน้ำเสียง
3. **นักศึกษาแลกเปลี่ยน** ใช้ "ขาออก" และ "ขาเข้า"

ข้อความแจ้งผลการเผยแพร่ใช้ "เผยแพร่ข้อตกลงแล้ว" และ "หยุดเผยแพร่ข้อตกลงแล้ว" เพื่อไม่ให้ซ้ำกับป้ายสถานะ "เผยแพร่แล้ว"
ช่องเลขบัญชีนักศึกษาในฟอร์มนักศึกษาแลกเปลี่ยนยังเป็นช่องพิมพ์ตัวเลข การเปลี่ยนเป็นรายการให้เลือกต้องมี API รายชื่อผู้ใช้ก่อน
